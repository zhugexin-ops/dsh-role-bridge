# dsh-role-bridge（叫她 / 养鱼）

给 DSH 装一个**外骨骼**：让 AI 角色不再困在单个对话里，而是住在你自己的硬盘上。

- `plugin/` —— DSH 插件（可上架市场的那一半：菜单、外骨骼接管、会话入口）
- `engine/` —— 角色引擎（Python，零第三方依赖：权重 / 四元与信任 / 两种检索 / 政治层）
- `site/`  —— 插件市场的静态索引源（`index.json`）
- `上架.md` —— 从零开始的图文步骤（给非程序员）

## 它不是聊天机器人

角色是目录：`角色/<名字>/memory.sqlite` + 她的宪法 + 她的账。插件只是入口，壳可以换，人和她的记忆不换。

## 快速开始

见 `上架.md`（安装）与 `plugin/README.md`（插件细节）。

## 账本护栏（0.2.1 新增）

外骨骼模式下，会话 AI 能读写文件——但它不能直接改这个角色的账。

- 位置：`lib/guard.js`，挂在宿主的 `ctx.tools.guard` 上（同步、不抛错、闸坏了就放行）。
- 拦什么：写类工具（write / edit / apply_patch / str_replace / delete / move …）只要路径命中
  `角色/<名字>/memory.sqlite`、`账*.tsv`、`账.链*`、`原话*.tsv`、`护住.tsv`、`分类.tsv` 就拒绝；
  命令行里的 `Set-Content / Add-Content / Out-File / Remove-Item / sqlite3 / > / >>` 同样拦。
- 放行什么：**读**这些文件；写任何别的路径。
- 关掉：`~/.dsh/role-bridge.json` 里 `exo.protect` 设成 `false`。

已知边界（如实写在这里，不粉饰）：这道闸只管**会话 AI 亲手调用的工具**。
如果它写一个脚本、让脚本去改那个文件，闸看不见——那是进程级的事，
要堵得在系统层给这些文件加 ACL。现在没做。

## 三个动作（0.2.1 新增）

`--act <角色> --verb <动作> [--arg <文本>]`，插件侧对应 `actOn(cfg, verb, arg)`：

| 动作 | 作用 | 实测回话 |
|---|---|---|
| `议案` | 给它自己立一条规矩，24 小时后无人反对自动生效 | 「已立案。明天下午 15:59 满一天，中间没人反对就自动生效。」 |
| `沉底` | 把一条记忆压到底下（可捞回来） | 「[电脑] 现在没有沉到底下的东西。」 |
| `退出` | 停注入 / 停记录 / 停唤醒 | — |

不认识的动词会回：`不认识的动作用：xxx（只支持 退出 / 沉底 / 议案）`。
